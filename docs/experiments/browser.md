## WEB-01 — Geometry is not actionability

- **Why/question:** Can real browser border boxes satisfy explicit geometric obligations after interaction, while keeping presence, absence and actionability as separate claims?
- **Setup/version:** Original static HTML/CSS/JS specimen on CachyOS; Node LTS 24.21.0/Bun 1.4.3, Playwright Test 1.64.1, Chromium headless shell revision 1248 (156.0.8078.4). Two viewports: 320×720 and 1024×768; independently authored widths 200.5 and 360.25, height 48, tolerance 0.02. Actual unforced button interaction precedes normal acquisition.
- **Observations:** Twelve full tests across both viewports and four individually selected metric runs exercised fractional boxes, actual CSS 47-height defect/48 repair with unchanged policy, missing observations, qualified absence, connected zero-size presence, duplicate identity refusal and origin/identity checks. A covering overlay left geometry passing but timed out a real unforced click with unchanged state. Overlay removal restored actual interaction and geometry. The expected action failure was asserted inside a normally passing control, not inverted into an accepted UI obligation. Wrong-run/checkpoint/candidate consumer mutations were labelled offline counterfactuals, not fresh interactions.
- **Failures/corrections:** Initial setup used an unsupported CLI subpath; a later selected-name filter also failed. Both failures were retained and only affected paths resumed. Later raw-file integrity review is a separate correction (WEB-02), not grounds to call all earlier receipts byte-correct.
- **Lesson/decision:** Use `web-dom-border-box` with layout/window/logical-px and a viewport-specific space. `getBoundingClientRect()` CSS pixels map 1:1 here: no DPR division or rounding. Root x16/y24 is an independent ordinary origin assertion, not a new comparator x/y metric. Missing observations cannot establish absence without qualified complete scope; zero size is not absence. Reuse Playwright actionability for actual interaction claims.
- **Limits:** One synchronous acquisition callback reads scoped identity, rectangles and readiness without DOM writes/awaits; it is not an atomic paint/screenshot transaction. The deliberately static envelope excludes animations, transforms, scrolling, external image/font resources, frames/shadow roots and asynchronous rendering. Mutation records do not prove compositor/CSSOM stability. Screenshots are contextual, not numerical or hit-testing certificates. CachyOS launched an upstream-selected Ubuntu payload; that is a local result, not official distro certification, native evidence or an arbitrary-page collector.
- **Evidence:** [Executed browser controls and semantics](../../examples/browser/README.md#declared-policy-and-controls), [policy/matrix](../../examples/browser/scenario.mjs), [acquisition](../../examples/browser/acquire.mjs), [ordinary tests](../../examples/browser/browser.spec.mjs), [historical failures](../../plans/extract-boopstick.md#notes). Original raw observations, screenshots, failed setup/filter outputs and independent review receipts remain privately retained.

## WEB-02 — Hash persisted bytes, then verify the referenced file

- **Why/question:** Does a raw-evidence digest identify the actual saved file, or merely a different serialization of the same parsed object?
- **Setup/version:** Same pinned specimen/toolchain as WEB-01. Independent review followed the initial producer qualification; the affected correction used full-only invocations rather than repeating unrelated selected/setup campaigns.
- **Observations:** Review found actual digest mismatches: the producer hashed compact object serialization while writing formatted JSON. Serialization is now performed once; identical bytes, including formatting/newline, are written and hashed. The consumer resolves the owned raw-file reference, reads it, checks its byte SHA-256 and checks parsed observation equality with the receipt. Correct copies pass; whitespace tamper, missing files and a substituted observation with a self-consistent file hash refuse.
- **Failures/corrections:** One affected local full invocation and one independent affected full invocation each passed twelve tests. Independent inspection verified 26/26 original receipt/raw references, 26/26 attached copies and 32/32 reference occurrences including labelled counterfactuals. The finding closed with no new findings; 187 historical source/evidence files remained hash-identical. Earlier selected/setup receipts retain historical mismatches: they were neither rerun nor retroactively certified.
- **Lesson/decision:** Object equality is not byte identity; a self-consistent replacement hash is not receipt consistency. Qualify both the writer and the independent consumer's file verification. Keep run/checkpoint/candidate/fixture/viewport/declaration bindings outside the comparator rather than assuming `rawEvidence` metadata verifies itself.
- **Limits:** File integrity and declared bindings are not loaded-code attestation or producer authenticity. Collection duration is not wall-clock freshness. The corrected full runs do not assert fresh selected/setup proof or a newly packed archive.
- **Evidence:** [Public raw-byte correction account](../../examples/browser/README.md), [single-serialization producer](../../examples/browser/acquire.mjs), [`requireCurrent` consumer](../../examples/browser/scenario.mjs), [qualification/attachment checking](../../examples/browser/qualify.mjs). Historical mismatches, correction outputs and independent byte-reference/tamper receipts are privately retained; no raw public download is claimed.

## WEB-03 — Cleanup is an observed result, not a fixture declaration

- **Why/question:** Can a finite browser trial leave its owned contexts, server and browser processes closed without touching user/shared resources?
- **Setup/version:** Same trial; standard page/context fixtures and a loopback-only `webServer` refusing an existing listener. Owned cache/output paths, no persistent profile, logged-in tab or external/private site.
- **Observations:** After the corrected full qualification, twelve contexts closed, owned browser/server PIDs disappeared and the loopback connection refused. Independent verification and parent acceptance included the bounded cleanup result.
- **Failures/corrections:** Historical setup/filter failures stayed retained; successful teardown does not turn those into completed metric invocations. No separate cleanup failure is reported in the public browser summary.
- **Lesson/decision:** Record terminal context/process/listener observations after runner exit. Fixture ownership alone is intent, not proof; cleanup is scoped to resources the trial owns.
- **Limits:** Host-specific lifecycle evidence is not a portable process manager or permission to terminate unrelated processes. Writer logs and independent verification remain distinct; documentation alone proves neither execution nor cleanup.
- **Evidence:** [Lifecycle boundary and observed correction result](../../examples/browser/README.md), [finite qualification lifecycle checks](../../examples/browser/qualify.mjs), [standard fixture configuration](../../examples/browser/playwright.config.mjs). Raw context/server/process observations and review receipts remain privately retained.
