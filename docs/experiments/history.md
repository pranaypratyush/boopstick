# Intent and project history

Boopstick grew out of a broader, method-first UI-verification effort; a standalone executable was not the original unconditional goal. This history separates that intent, later approved scope, engineering choices and delivered evidence. For today's architecture, use [current design](design.md); for failure details, use the [experiment index](README.md).

## Intent and attribution

- **Original intent — sanitized paraphrase of retained private assignment and specification records:** generalize a useful product-local UI-verification method into optional, reusable guidance, usable without adopting orchestration. The acceptance seam was **scenario → evidence bundle → project-owned review**. Design parity, visual regression, measured layout/text and behavior/accessibility/composition remained distinct claims. Product references, tolerances, deviations and acceptance stayed project-owned.
- **Original approved delivery design — specification, not a verbatim user quotation:** proceed method-first through shared guidance (UV1), originating-project adoption (UV2), independent real-consumer qualification (UV3), then a decision about executable extraction (UV4). Extraction was conditional on demonstrated reuse; remaining method-only was a valid outcome. Those stages were not a blanket execution or publication grant.
- **Later accepted Boopstick scope — public approved plan/specification:** cleanly extract the cleared comparator and an agent-neutral standalone skill; preserve behavior; use ordinary RNTL/Jest and Vitest tests plus separately qualified real-browser and Android paths. This separately authorized package effort was not evidence that all original method-stage prerequisites had completed. See the [accepted plan](../../plans/extract-boopstick.md) and [specification](../../specs/boopstick.md).
- **Later user operating directions — exact words supplied in the retained conversation context:** “then proceed with that, find local android emulators and use them”; “ignore github CI entirely, only local validation is applicable”. These governed later execution and validation; they are not timeless package API requirements. Later user direction authorized finishing public onboarding, release and inventoried consumer cutover already planned in the original accepted PR1 Phase E; it did not introduce new scope. The present knowledge-base request is a further documentation increment.
- **Rights and engineering decisions — separate from original intent:** an actual scoped owner grant authorized Apache-2.0 redistribution of selected owned comparator code, independent fixtures and generic prose, excluding unclear third-party material and private assets/history. That was not registry-release permission. Exact contract 3.1, compiled ESM/declarations, the offline CLI, self-contained skill references and external capture producers describe the accepted extraction design, not words attributed to the original user. [Public provenance](../provenance.md) records the cleared derivation boundary.

The original-intent summaries above are newly authored from private primary/contextual records; they are not reconstructed quotations or publicly retrievable transcripts. Only the two explicitly marked later directions are quoted. Public plan/spec prose records accepted requirements and implementation choices, not a verbatim transcript of every user decision.

## Current state and open limits

**0.1.0 is published and independently onboarded; the approved inventoried cutover is complete within its qualified scope.** The [release](https://github.com/pranaypratyush/boopstick/releases/tag/v0.1.0) is authoritative for post-tag onboarding/cutover status; the tagged plan/spec preserve earlier checkpoints. PR2/3 remain unadopted proposals, and downstream review branches remain deliberately unmerged. Local validation is the acceptance basis; no hosted-CI success is claimed.

Boopstick compares explicit obligations against supplied observations; drivers and capture producers remain external. The recorded browser/Android specimens do not establish iOS, physical-device support, general transport reliability, loaded-code attestation or whole-interface correctness. The Android host restriction and unresolved earlier target-loss cause remain. Package release, neutral integration proof and upstream method simulations do not automatically establish original UV2 adoption, UV3 independent real-consumer method qualification or UV4's original two-consumer obligation; even full UV1 stage acceptance is not asserted by the later simulations.

**Evidence confidence:** public scope, derivation, qualification summaries and release status have linked public sources; original intent and staged authority rely on retained private records summarized honestly above. This document does not supply public reproduction of those receipts, missing milestone dates, a causal explanation for target loss or authority to accept a parent project's UI. No experiments were rerun to author it.
