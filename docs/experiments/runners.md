## RUN-01 — Select one obligation; account for the complete matrix

- **Why/question:** Can ordinary Jest/Vitest cases provide useful isolated feedback without allowing a partial green run to approve all declared obligations?
- **Setup/version:** Packed package consumption, no source imports. Node LTS 24.21.0/Bun 1.4.3; Vitest 5.0.5/Vite 8.3.4; Jest 30.5.2, React 19.3.1, RN 0.88.0, RNTL 14.1.0, Test Renderer 1.3.1. Width/height IDs derive from the intact synthetic request before collection. Built-in Vitest JSON/meta and Jest JSON with a file-local append-only evidence attachment supply results, not a new runner or registry.
- **Observations:** Nine real controls per consumer covered full, filtered width, passing width with failed height sibling, skipped height, expected-failing height, measured mismatch, missing observation, invalid request and invalid capture. Width and height also passed individually. Only complete correct invocations satisfied full accounting. A complete comparator report did not discharge a skipped/unexecuted runner case; each executed case selected its unique assertion outcome, not aggregate status. Capture admission errors retained empty outcomes and capture-wide diagnostics.
- **Failures/corrections:** RNTL's first run failed four queries because native ESM named `screen` retained the initial reassigned CJS export. Callers switched to queries from `const view = await render(...)`; the affected RNTL-only gate passed. No comparator shim or custom environment was added. An earlier orchestration error was retained separately, not counted as a runner execution. Original failures and successful Vitest results were preserved.
- **Lesson/decision:** Register from declarations, compare the intact input, assert one outcome locally, then reconcile exact IDs, multiplicities and independent run/artifact/request/environment/project/file bindings for full acceptance. Expected-failure inversion and skips cannot satisfy UI obligations. RNTL uses awaited interactions, normal cleanup and existing behavior/state matchers.
- **Limits:** Supplied `fireEvent.layout` data is synthetic, not measured native geometry. Synthetic-as-live refusal (`not_measured/synthetic-not-live-evidence`) is a successful negative contract test, not UI acceptance. Metadata does not attest loaded code or measurement authenticity. Phase C did not repeat unchanged core/build campaigns.
- **Evidence:** [Executed controls, setup and selection recipe](../../examples/README.md#executed-qualification-and-retained-correction), [canonical scenario declarations](../../examples/shared/scenario.mjs), [reconciliation implementation](../../examples/shared/reconcile.mjs), [finite qualifier](../../examples/shared/qualify.mjs), [accepted test ergonomics](../../specs/boopstick.md#test-ergonomics-and-complete-ci). Failed/corrected runner reports and independent bindings remain privately retained.

## RUN-02 — Challenge malformed evidence after the happy path passes

- **Why/question:** Does result reconciliation refuse ambiguous or malformed reports, including evidence that looks green at the runner level?
- **Setup/version:** Same pinned consumers as RUN-01. The initial campaign rejected 23 explicitly labelled report counterfactuals per consumer. They mutate retained report evidence; they are not claims that runners executed those fabricated states.
- **Observations:** Probes covered omitted/duplicate/conflicting IDs, equal-count duplicate-plus-omission, missing outcomes/attachments, stale or wrong identities, discovery-only records, and hidden comparator/expected-failure results. Supplemental independent probes nevertheless demonstrated two defects: acceptance of an unknown aggregate comparison status in both runner shapes, and missing/nonboolean Jest `failing` flags.
- **Failures/corrections:** Reconciliation now admits only aggregate `pass`/`fail`/`not_measured` after admission refusal, and requires Jest obligation rows to have `failing === false`. It still allows a passing selected sibling in an aggregate-failing report. Four exact discriminator cases were added to existing accounting checks. Targeted offline replay rejected 24 Vitest/26 Jest counterfactuals and preserved all 18 retained real-run dispositions and original diagnostics. Independent targeted verification closed both findings with no new findings; the original failing probes were retained.
- **Lesson/decision:** Validate evidence discriminators explicitly; green status and plausible counts are insufficient. Distinguish the runner's terminal result, inversion metadata, comparator admission and selected outcome. A broader replay matrix is not a larger runtime campaign.
- **Limits:** These correction results are offline report replays, not fresh runner/setup/core/build invocations. No new public adapter, API or report schema was needed. Parent acceptance is bounded to these ordinary-runner/synthetic paths.
- **Evidence:** [Correction account](../../examples/README.md#executed-qualification-and-retained-correction), [retained accounting probes](../../examples/shared/accounting-check.mjs), [fail-closed reconciliation](../../examples/shared/reconcile.mjs), [historical plan notes](../../plans/extract-boopstick.md#notes). The public source explains the checks; raw historical reports, failing supplemental probes and independent verification receipts are privately retained.
